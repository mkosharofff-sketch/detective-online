# ДЕЛО // ONLINE

> Устный детектив для Discord: один ведущий готовит дело, один детектив расследует его, а дополнительные игроки отыгрывают подозреваемых.

## Назначение игры

**«Дело // Online»** — не мафия, не голосование и не командное расследование.

В основе партии:

- свободные допросы в Discord;
- противоречия, ложь, алиби и личные интересы;
- секреты персонажей;
- факты, которые ведущий открывает по ходу расследования;
- логическое расследование одного детектива;
- одно единственное финальное обвинение.

## Роли

| Роль | Задача | Что видит |
|---|---|---|
| **Ведущий** | Придумывает дело, управляет темпом расследования, выдаёт факты, ведёт развязку | Всё: полное дело, истину, секреты, роли и обвинение детектива |
| **Детектив** | Расследует, вызывает подозреваемых на допрос, ведёт заметки, делает одно обвинение | Открытую карточку дела, список подозреваемых, выданные факты и собственные заметки |
| **Игрок-персонаж** | Отыгрывает назначенного подозреваемого | Только собственную приватную карточку; если он убийца — также мотив и способ |

## Правила партии

1. Ведущий выбирает роль «Я ведущий» и создаёт комнату.
2. Комната получает короткий код, который ведущий передаёт детективу и игрокам.
3. Ведущий **сразу** переходит в панель подготовки дела — ему не нужно ждать детектива в лобби.
4. Ведущий заполняет карточку дела, персонажей и скрытую истину.
5. Детектив заходит по коду через «Я детектив» и ждёт, пока ведущий запустит расследование.
6. Дополнительные участники могут зайти через «Я игрок» до или после запуска; их отсутствие не блокирует начало игры.
7. Ведущий вручную нажимает «Начать расследование».
8. Детектив вызывает подозреваемого на допрос, а разговор проходит голосом в Discord.
9. Ведущий раскрывает факты тогда, когда считает нужным.
10. Детектив отправляет **одно** финальное обвинение с объяснением.
11. Ведущий смотрит обвинение и открывает развязку.

## Что должно храниться в комнате

Игровая информация должна сохраняться в Firebase Realtime Database и оставаться доступной после обновления страницы, закрытия вкладки или переподключения участника.

### Открытая часть дела

Доступна участникам комнаты после нужной фазы игры:

- статус партии: подготовка / расследование / завершение;
- название дела;
- жертва;
- инцидент;
- вводная для детектива;
- локация;
- публичный список подозреваемых;
- открытые ведущим факты;
- текущий активный допрос;
- журнал завершённых допросов;
- опубликованная развязка.

### Приватная часть ведущего

Доступна только ведущему:

- полный список персонажей;
- скрытые секреты и личные цели;
- убийца;
- мотив;
- способ убийства;
- хронология;
- полная развязка;
- все приватные карточки игроков;
- заметки и финальное обвинение детектива.

### Приватная карточка игрока

Доступна только конкретному игроку и ведущему:

- имя персонажа;
- профессия или роль;
- архетип;
- отношения и связи;
- секрет;
- личная цель;
- для убийцы: мотив и способ.

### Приватные данные детектива

Доступны только детективу и ведущему:

- личные заметки;
- единственное отправленное обвинение;
- выбранный подозреваемый;
- текст обоснования;
- время отправки.

## Техническая база

| Компонент | Назначение |
|---|---|
| GitHub Pages | Публикация статического сайта |
| HTML + CSS + JavaScript | Интерфейс и клиентская игровая логика |
| Firebase Authentication | Анонимная идентификация браузеров и участников |
| Firebase Realtime Database | Комнаты, синхронизация партии и сохранение данных в реальном времени |
| Firebase Realtime Database Rules | Ограничение доступа к открытым и приватным данным |

Проект не использует PeerJS для подключения игроков. Старый PeerJS-макет может использоваться как референс интерфейса и игровой механики, но текущей основой должен оставаться Firebase.

## Целевая структура Firebase

Ниже — целевая логическая структура комнаты. Точные пути в Rules и JavaScript должны совпадать с ней.

```text
rooms/{roomCode}
├─ participants/{uid}
│  ├─ uid
│  ├─ name
│  ├─ role                 # host | detective | player
│  ├─ joinedAt
│  └─ characterId          # только для назначенного игрока
│
├─ public
│  ├─ status               # setup | investigation | finished
│  ├─ maxPlayers
│  ├─ createdAt
│  ├─ case
│  │  ├─ title
│  │  ├─ victim
│  │  ├─ incident
│  │  ├─ intro
│  │  └─ location
│  ├─ suspects
│  ├─ facts                # только выданные ведущим факты
│  ├─ activeInterrogation
│  ├─ interrogationLog
│  └─ endingPublished
│
├─ hostPrivate
│  ├─ hostUid
│  ├─ characters           # полные карточки всех персонажей
│  └─ truth
│     ├─ killerId
│     ├─ motive
│     ├─ method
│     ├─ chronology
│     ├─ facts
│     └─ ending
│
├─ playerPrivate/{uid}
│  ├─ characterId
│  ├─ name
│  ├─ profession
│  ├─ archetype
│  ├─ relations
│  ├─ secret
│  ├─ personalGoal
│  └─ murdererInfo         # только если этот персонаж — убийца
│
└─ detectivePrivate/{uid}
   ├─ notes
   └─ accusation
      ├─ suspectId
      ├─ suspectName
      ├─ reason
      └─ submittedAt
```

## Требования безопасности

Интерфейс сам по себе не защищает секреты: если данные уже загружены браузеру детектива, их можно увидеть через DevTools. Поэтому скрытая истина и секреты не должны храниться в одной публично читаемой ветке комнаты.

Минимальные требования к Firebase Rules:

- участник читает только `public` и собственные разрешённые приватные ветки;
- ведущий читает и изменяет `hostPrivate`;
- игрок читает только `playerPrivate/{свой uid}`;
- детектив читает и изменяет только `detectivePrivate/{свой uid}`;
- ведущий может читать карточки игроков и обвинение детектива;
- только ведущий изменяет описание дела, персонажей, истину, список подозреваемых и выдаваемые факты;
- детектив может вызвать допрос и сделать обвинение;
- обвинение нельзя изменить или отправить второй раз;
- игрок не получает доступ к чужим карточкам и полной истине.

## План разработки

### Этап 1. Стабилизация запуска

- Прочитать актуальный `index.html` из репозитория.
- Исправить JavaScript-ошибку, из-за которой сайт зависает на «Подключение…».
- Убедиться, что стартовый экран появляется даже до создания или входа в комнату.
- Проверить Firebase imports, анонимную авторизацию и обработку ошибок.

### Этап 2. Согласование базы и Rules

- Зафиксировать одну структуру данных комнаты.
- Сопоставить каждый путь JavaScript с Firebase Rules.
- Исключить чтение всей комнаты детективом и игроком, если в ней находится `hostPrivate`.
- Реализовать корректное присоединение нового участника к комнате.

### Этап 3. Панель ведущего

- Сохранение карточки дела.
- Добавление, редактирование и удаление персонажей.
- Автоматическое обновление публичного списка подозреваемых.
- Заполнение истины, убийцы, мотивов, хронологии и выдаваемых фактов.
- Назначение игрока персонажу.
- Предпросмотр того, что увидит детектив или конкретный игрок.

### Этап 4. Игровой цикл

- Экран ожидания детектива.
- Ручной запуск расследования ведущим.
- Вызов персонажа на допрос детективом.
- Отображение активного допроса у ведущего.
- Завершение допроса ведущим и журнал допросов.
- Ручная выдача фактов.
- Автосохранение заметок детектива.
- Одно финальное обвинение с обоснованием.
- Просмотр обвинения ведущим.
- Публикация развязки.

### Этап 5. Проверка ролей

Проверять нужно минимум в трёх независимых браузерных сессиях:

1. Ведущий — обычное окно Chrome.
2. Детектив — режим инкогнито или другой браузер.
3. Игрок — второй браузер, второй профиль или телефон.

Тестовая последовательность:

1. Ведущий создаёт новую комнату.
2. Ведущий заполняет дело и трёх персонажей.
3. Детектив входит по коду и видит ожидание.
4. Игрок входит по коду.
5. Ведущий назначает игроку персонажа.
6. Ведущий запускает расследование.
7. Детектив видит открытое дело и список подозреваемых.
8. Детектив вызывает персонажа на допрос.
9. Ведущий видит активный допрос и завершает его.
10. Ведущий выдаёт факт — детектив видит его без перезагрузки.
11. Детектив записывает заметку, обновляет страницу и проверяет сохранение.
12. Детектив отправляет обвинение.
13. Детектив пытается отправить второе обвинение — действие должно быть запрещено.
14. Ведущий видит обвинение и открывает развязку.
15. Игрок проверяет, что он не видит чужие карточки, истину и обвинение.

## Принципы дальнейшей разработки

- Не возвращать PeerJS как основу сетевой логики.
- Не создавать новый Firebase-проект.
- Не повторять базовую настройку Firebase, GitHub Pages или Anonymous Authentication без конкретной технической причины.
- Не хранить секреты и истину в публичной ветке Firebase.
- Не делать игру мафией, голосованием или командным расследованием.
- Любое изменение должно проверяться на новой тестовой комнате, если менялась структура базы или Firebase Rules.
- Перед публикацией правки проверять консоль браузера и поток ведущий → детектив → игрок.

## Быстрая диагностика

Если сайт показывает шапку, но остаётся на **«Подключение…»** и не рисует форму ролей:

1. Открой опубликованный сайт.
2. Нажми `F12`.
3. Перейди во вкладку **Console**.
4. Нажми `Ctrl + F5`.
5. Скопируй красную ошибку вместе со строкой вида `index.html:123`.

Это позволяет найти точную причину до изменения Firebase Rules или кода наугад.
